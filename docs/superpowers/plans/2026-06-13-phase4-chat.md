# Phase 4 — 채팅 개편 구현 계획 (백엔드/프론트 병렬 트랙)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. 트랙 A(백엔드)·트랙 B(프론트)는 별도 에이전트 병렬 실행. 「공통 SSE/API 계약」은 양쪽 절대 기준.

**Goal:** spec §5 — 채팅 내 만세력 선택 → 하이브리드 첨부(+버튼/바텀시트/칩 + 궁합 시 인라인 선택 카드) → tool 결과 인라인 차트 렌더 → 궁합 tool → 세션 title 자동 생성. 캔디 브루탈 리스킨.

**참조:** spec §5(5.1~5.4)·§7.5, design.md §4.5(말풍선)·§6(톤), 목업 v10 채팅 화면. 기존 백엔드: `routers/chat.py`(SSE `astream_events`), `llm/pipelines/chat.py`(LangGraph ReAct), `llm/tools/saju_tools.py`(12 tool), `engine/handlers/check_compatibility.py`(궁합 엔진 — 이미 존재).

## 공통 SSE/API 계약 (양 트랙 절대 기준)

### 세션 생성 — 상대방 프로필 수용
```
POST /api/chat/session
  body: { profile_id? | birth_date,birth_time,gender,calendar,is_leap_month }  # 기존 그대로
  → ChatSessionResponse { id, title, birth_info, last_message_at, created_at }
```

### 상대방(궁합) 프로필 첨부 — 신규
```
POST /api/chat/{session_id}/partner
  body: { profile_id? | birth_date,birth_time,gender,calendar,is_leap_month, name? }
  → 200 { partner_name: string }    # 세션 상태에 상대 사주 요약 저장
DELETE /api/chat/{session_id}/partner → 204
```

### 메시지 스트림 — SSE 이벤트 타입 (현행 token/done 에 추가)
```
data: {"type":"token","content":"..."}                      # 기존
data: {"type":"tool_result","tool":"get_dae_un","payload":{...}}   # 신규 — 인라인 카드 렌더용
data: {"type":"request_partner"}                            # 신규 — 인라인 선택 카드 트리거
data: {"type":"title","title":"3월 이직 타이밍 상담"}          # 신규 — 첫 턴 후 자동 생성된 제목
data: {"type":"done"}                                       # 기존
```
- `tool_result.payload`는 tool별 구조화 데이터(차트 렌더용). tool 이름 → 프론트 컴포넌트 매핑은 트랙 B 소관.
- `request_partner`: agent가 `request_partner_profile` tool을 호출하면 방출. 프론트가 인라인 만세력 선택 카드 표시.

```typescript
// 트랙 B: packages/api-client/src/chat.ts (기존 타입 있으면 확장)
type ChatStreamEvent =
  | { type: 'token'; content: string }
  | { type: 'tool_result'; tool: string; payload: Record<string, unknown> }
  | { type: 'request_partner' }
  | { type: 'title'; title: string }
  | { type: 'done' }
```

영역: 트랙 A=backend만, 트랙 B=apps/web·packages만.

## 트랙 A — 백엔드 (모델: opus)

### A1. 궁합 tool + request_partner tool (TDD)
- `llm/tools/saju_tools.py`에 추가:
  - `get_compatibility_detail` — 세션의 birth_info(본인) + 첨부된 partner 사주로 `handle_check_compatibility` 호출, 결과 요약 반환. partner 미첨부면 "상대 정보 필요" 신호 반환
  - `request_partner_profile` — agent가 궁합 질문 감지 시 호출하는 시그널 tool (반환은 "상대 만세력 첨부 요청됨", 그래프가 SSE `request_partner` 방출 트리거)
- partner 사주는 `RunnableConfig.configurable["partner_info"]`로 주입 (birth_info 패턴과 동일)
- `CHAT_TOOLS`에 2개 등록, 시스템 프롬프트(`prompts/chat.py`)에 "궁합 질문 시 상대 만세력이 없으면 request_partner_profile을 먼저 호출" 지침 추가
- 테스트: 궁합 tool(스텁 partner), request 시그널, partner 없을 때 동작
- 커밋: `feat: 궁합·상대 프로필 요청 tool 추가`

### A2. 세션 partner 상태 + 엔드포인트
- `ChatSession`에 `partner_info: JSONB nullable` 컬럼 + 마이그레이션 (Phase 3가 0009까지 → 0010)
- `POST/DELETE /api/chat/{id}/partner` (router→service→crud, backend/CLAUDE.md 3-레이어). partner 사주 요약은 메시지 스트림 config에 주입
- 테스트: 첨부/제거, 권한
- 커밋: `feat: 채팅 상대 프로필 첨부 API 추가`

### A3. SSE 이벤트 확장 — tool_result·request_partner·title
- `routers/chat.py`의 `event_stream`에 astream_events 처리 추가:
  - `on_tool_end` 이벤트 → tool 이름·출력을 `tool_result`로 (단 차트 렌더 대상 tool만 화이트리스트: get_dae_un·get_wol_un·get_yeon_un·get_daily_fortune·get_il_jin·get_compatibility_detail. payload는 tool이 반환한 구조화 dict — **tool들이 문자열 대신 dict도 반환하도록 점진 조정**하거나, tool_result용 별도 직렬화)
  - `request_partner_profile` tool 호출 감지 → `request_partner` 방출
  - **첫 어시스턴트 응답 완료 후**(세션의 첫 턴) title이 없으면 경량 LLM 1회로 제목 생성(≤20자) → DB 저장 + `title` 이벤트
- 기존 token/done 동작 보존
- 테스트: 이벤트 시퀀스(스텁 그래프), title 생성 1회성
- 커밋: `feat: 채팅 SSE에 tool 결과·상대 요청·제목 이벤트 추가`

### A4. 검증
`uv run pytest -q` 전체 그린 + 기존 채팅 테스트 회귀 없음. tool이 구조화 payload를 주는지 계약 대조. LLM 실호출 금지(스텁).

> tool 반환 형식 주의: 현재 tool들은 문자열 반환(agent 추론용). 차트용 구조화 데이터가 필요하므로 **tool은 문자열 유지하되, on_tool_end에서 원본 dict를 얻는 방법**(tool 내부에서 dict를 만들고 json.dumps 문자열로 반환 → SSE에서 재파싱, 또는 tool이 `{"summary": str, "data": dict}` 형태 반환)을 A1에서 결정하고 A3와 일관되게. 어느 쪽이든 agent 추론은 summary 텍스트를, 프론트는 data를 쓰게.

## 트랙 B — 프론트 (모델: sonnet)

기존: 레거시 `frontend/pages/chat/*.vue`(SSE 파싱 참고용), web엔 `/chat` 라우트 **없음**(홈/만세력 카드가 `/chat` 링크만 가짐 — 404 상태). 분석 화면 차트 컴포넌트(`components/manse/*`) 재사용 가능. `serverAuthApi`, `lib/manse/query.ts`, 마스코트.

### B1. api-client — chat 함수 + SSE 파서 (TDD)
`packages/api-client/src/chat.ts`: 세션 CRUD 타입·함수 + partner 첨부/제거 + `ChatStreamEvent` 타입. **SSE 스트림 파서**는 `@sajuguri/core`에 두기(RN 재사용 — G1): `parseSSEStream(response): AsyncIterable<ChatStreamEvent>` (EventSource 미사용, fetch ReadableStream 기반 — RN 호환). 테스트: SSE 청크 → 이벤트 파싱(분할 청크·여러 이벤트 포함). 커밋: `feat: api-client 채팅 함수와 SSE 파서 추가`

### B2. 채팅 세션 목록 — `/chat`
- 서버 컴포넌트: `listSessions`. 비로그인 → 로그인 유도. [새 상담] → 만세력 선택 시트(운세의 `FortuneEntrySheet` 패턴 재사용 또는 공용화) → `createSession` → `/chat/{id}`
- 커밋: `feat: 채팅 세션 목록 화면`

### B3. 채팅 화면 — `/chat/[id]` (핵심)
- 클라 컴포넌트. 헤더(← 세션명) + **첨부 칩 줄**(본인 만세력 칩 + 궁합 시 상대 칩, 칩 = `Chip` 컴포넌트 틸 틴트)
- 메시지 영역: 유저 말풍선(옐로+잉크 보더, 우측), AI 말풍선(화이트+틸 보더+마스코트 아바타, 좌측) — design.md §4.5
- **입력바**(하단 fixed): `+` 원형 버튼(만세력/상대 첨부 바텀시트) + 필 입력창 + 오렌지 전송 버튼
- **SSE 전송**: `parseSSEStream` 소비 → token은 마지막 AI 말풍선에 누적, **tool_result는 인라인 카드**(B4), request_partner는 인라인 선택 카드(B5), title은 헤더 갱신
- 커밋: `feat: 채팅 화면 구현 (말풍선·입력바·SSE)`

### B4. tool 결과 인라인 차트 — 컴포넌트 매핑
- `components/chat/ToolCard.tsx`: `tool` 이름 → 컴포넌트 매핑. 분석 화면 차트의 **컴팩트 변형** 재사용:
  - get_dae_un → 대운 미니 타임라인, get_wol_un → 월운 미니 바, get_daily_fortune → 점수 카드, get_il_jin → 일진 요약, get_compatibility_detail → 궁합 점수 카드
  - 미매핑 tool → 렌더 생략(텍스트만)
- 말풍선 사이 들여쓰기 배치 (AI 아바타 정렬)
- 커밋: `feat: 채팅 tool 결과 인라인 카드 렌더`

### B5. 하이브리드 첨부 — 칩 + 인라인 선택 카드
- `+` 버튼 바텀시트: 본인 만세력 교체 / 상대 만세력 첨부(저장 목록+직접 입력) → `attachPartner` → 칩 추가
- `request_partner` 이벤트 수신 시 **대화 흐름에 인라인 만세력 선택 카드** 표시 → 선택 시 attachPartner 후 직전 질문 재전송(또는 "첨부됨" 후 사용자 재질문 유도)
- 커밋: `feat: 채팅 하이브리드 프로필 첨부 (칩·인라인 카드)`

### B6. 검증
`pnpm build/test/typecheck` 그린. SSE 파서·인라인 카드 매핑 로직 테스트. 백엔드 미가동 시 목록/화면 에러 fallback.
