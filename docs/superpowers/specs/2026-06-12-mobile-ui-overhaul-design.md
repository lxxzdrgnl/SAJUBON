# 모바일 우선 UI 개편 — 설계 문서

> 작성일: 2026-06-12
> 상태: 사용자 리뷰 대기
> 토픽: 채팅 개편 + 10탭 리포트 프론트 + 운세 스토리 + MZ 리스킨 + IA 재편

---

## 1. 배경과 목표

### 1.1 현황
- **채팅 Agent**(4/30 spec)는 백엔드·프론트 모두 동작하나, 채팅 페이지가 사이트 디자인
  시스템 밖(raw Tailwind 하드코딩)이고 프로필 첨부·리치 컴포넌트가 없다.
- **10탭 AI 리포트**는 백엔드 완성(`POST /api/saju/report`, Writer가 10탭 생성),
  **프론트 UI가 전무**하다.
- **오늘의 운세**는 엔진 기반(LLM 없음)으로 동작하나 일반 폼+결과 페이지 형태다.
- PC/모바일 반응형 분기가 화면마다 제각각이다.

### 1.2 목표 (Goals)
- **모바일 단일 컬럼으로 전 화면 통일** — PC 전용 레이아웃 폐기, 데스크탑은 좌우 여백
  (ForceTeller 패턴). 6/2 멀티 도메인 spec §7.0(PC 2단)은 **폐기**로 갱신.
- 하단 탭 4개 IA + 홈 콘텐츠 허브 도입
- 10탭 리포트 프론트 구현 (헤드라인 아코디언 + 구조화 섹션)
- 채팅 개편: 만세력 첨부(하이브리드) + tool 결과 인라인 컴포넌트 렌더
- 오늘의 운세를 Wrapped/인스타 스토리 형식으로 재구축 (만세력별 1일 1회)
- 네오 브루탈리즘(택시 옐로) + 너구리 마스코트로 전면 리스킨

### 1.3 비목표 (Non-Goals)
- moonmarin8 ETL·RAG 보강·신규 도메인 (6/2 spec P1~P6 로드맵 그대로 유지)
- 궁합 batch 리포트 도메인 (채팅 궁합 tool만 이번 스코프)
- 앱 패키징 (PWA/Capacitor — 추후)
- 게스트 채팅·게스트→로그인 프로필 병합 (추후)

## 2. 정보 구조 (IA)

### 2.1 하단 탭 4개
| 탭 | 내용 |
|---|---|
| 🏠 **홈** | 콘텐츠 허브 — 오늘의 운세 배너(스토리 진입), 리포트·상담 카드, 한줄상담(게스트 맛보기), coming soon 도메인 카드 |
| 🀄 **만세력** | 만세력 목록/등록(입력폼). 카드 탭 → 만세력 분석 화면, 카드 버튼으로 [AI 리포트] [상담] 진입 |
| 💬 **상담** | 채팅 세션 목록 → 채팅 (재방문 잦아 전용 탭 유지) |
| 👤 **마이** | 기록 보관함(리포트 기록·운세 기록 날짜별) + 계정 관리 |

- 운세·리포트는 전용 탭 없이 홈/만세력에서 진입하는 풀스크린 페이지.
- 기존 페이지 정리: `/daily`(폼+결과) → 스토리로 대체·폐기, `/question` → 홈의
  게스트 맛보기 카드로 유지(리스킨만), `/my-profiles` → 만세력 탭으로 흡수.

### 2.2 레이아웃
- 전 화면 모바일 단일 컬럼 `max-width: 640px` 가운데 정렬, 데스크탑은 양옆 여백.
- 채팅의 PC 사이드바(`hidden md:flex`) 제거 → 세션 목록은 상담 탭 화면으로 일원화.

### 2.3 권한 (게스트/로그인)
| 기능 | 게스트 | 비고 |
|---|---|---|
| 만세력 계산 | ✅ | localStorage에 최근 입력 저장·자동완성 |
| 운세 스토리 | ✅ | 게스트는 localStorage 캐시로 1일 1회 동작 |
| 한줄상담 | ✅ | 로그인 전환 유도 퍼널 |
| 10탭 리포트 | ❌ 로그인 | 생성·보관·공유 모두 계정 종속 |
| 채팅 상담 | ❌ 로그인 | 세션 영속성 |
| 공유 링크 열람 | ✅ | 리포트·운세 공유본은 비로그인 읽기 전용 |

## 3. 디자인 시스템 — 네오 브루탈리즘 "비비드 캔디" + 너구리

> 목업 8차 반복(v1~v8, `.superpowers/brainstorm/`)으로 사용자와 확정한 값.

- **팔레트 (비비드 캔디)**:
  | 토큰 | 값 | 용도 |
  |---|---|---|
  | 배경 | `#FFFBF2` | 전 화면 베이스 |
  | 옐로 (주연) | `#FFD900` | 활성 탭, 주요 CTA, 로고 하이라이트, 유저 말풍선 |
  | 오렌지 (강조) | `#FF6B00` | 호버/프레스, 강조 뱃지, 차트 피크, 흉살 칩 틴트, 전송 버튼 |
  | 틸 (보조) | `#00C2B8` / 딥 `#00857D` / 틴트 `#D7F7F4` | AI 요소(말풍선 보더), 정보·보조 행동(공유), 길신 칩, 차트 저점, 홈 운세 배너 |
  | 잉크 | `#1A1A1A` | 보더·텍스트·오프셋 섀도 |
  기존 CSS 변수(`--bg-base`, `--surface-1`, `--accent`…) **값 교체**로 전면 리스킨 후 페이지별 보정.
- **오행 5색 (팔레트 파생)**: 목 `#00A86B` · 화 `#FF6B00` · 토 `#D9A400` ·
  금 `#7D7A70` · 수 `#0090A8`. 만세력 표·차트·간지 글자에 일관 사용 (전통 5색 폐기).
- **브루탈 강도 2단계**: 강조 요소(배너·CTA·활성 탭·태그 칩)는 풀 브루탈(2px 잉크
  보더 + 오프셋 섀도), 장문 텍스트 영역(리포트 본문·AI 말풍선)은 저강도(얇은 보더,
  섀도 없음). **그라데이션은 스토리 전용** — 앱 본체 카드/배너는 단색.
- **칩 규칙**: 모든 칩은 잉크 보더 + 미니 오프셋 섀도로 통일. 의미는 배경 틴트로만
  구분 (길신=틸 틴트, 흉살=오렌지 틴트, 일반=화이트).
- **아이콘**: 이모지 사용 금지(UI 요소에서). 미니멀 스트로크 SVG 아이콘 세트
  (탭 바·기능 카드·버튼·마이 메뉴).
- **홈 운세 배너**: 앰버 `#FFB200` 단색 + 잉크 텍스트 + 마스코트 — 옐로 계열을
  유지하되 로고 옐로(`#FFD900`)보다 한 단계 진해 분리됨.
- **너구리 마스코트**: "사주구리=너구리" 브랜드 정체성. 사용자 제공 SVG를 택시 옐로로
  리컬러한 `frontend/public/mascot.svg`(저장 완료)를 파비콘·로고 옆·빈 상태·로딩·
  채팅 AI 아바타·스토리 진행자·요약 카드에 사용. 추후 일러스트 확장.
- **운세 스토리는 예외**: 풀스크린 비비드 그라디언트의 독립 무드 (인스타 스토리 문법).

## 4. 10탭 AI 리포트 (프론트 신규 + 백엔드 보강)

### 4.1 생성 동선
```
만세력 탭(또는 홈 카드) → 만세력 선택 → "추가로 보고 싶은 것" 입력(선택)
  → 생성(수십 초, 너구리 로딩) → 리포트 페이지 + DB 저장
```
- 입력란 의미: "고민"이 아니라 **리포트에 추가로 담길 주제 요청** (예: "이직 시기,
  부모님 건강도 봐줘"). Writer가 해당 주제 탭을 추가 생성. 기본은 사주 전체 해설.
- **매번 새로 생성** + 생성본은 전부 DB 저장. 마지막 생성본은 클라이언트 캐시
  (탭 이동 후 복귀 시 재생성·재과금 방지).
- 저장본은 **마이 탭 "내 리포트"**에서 날짜·만세력별로 재열람. share 토큰으로 공유
  (비로그인 읽기 전용, 기존 share 패턴 재사용).
- **공유 시 개인정보는 사용자 선택**: 공유 모달에서 "생년월일시 공개" 토글 —
  끄면 공유본에 일주·별칭만 표시하고 생년월일시 마스킹 (운세 공유도 동일 규칙).
- **생성 횟수 제한**: v1은 무제한. 단 `settings.report_daily_limit: int | None = None`
  설정값으로 구현해 추후 숫자만 넣으면 즉시 제한 가능하게 한다 (초과 시 429 + 안내).

### 4.2 리포트 페이지 구조 (위→아래, "샌드위치")
1. **원국 요약 카드** (접이식) — 4기둥 표 + 오행 분포 차트. 엔진 데이터 즉시 렌더,
   기존 컴포넌트(`SajuTable`/`WuxingDonutChart` 등) 재사용
2. 안내 문구: "각 제목을 클릭하면 해설이 펼쳐져요"
3. **10탭 헤드라인 아코디언** — ✨ + 결론형 헤드라인 카드 세로 나열(헤드라인이 곧
   목차), 탭하면 본문 펼침. 본문 3단 구성: **비유 스토리텔링 → 명리 근거 → 현실 조언**
4. **올해의 흐름** — 상/하반기 카드 + 월별 12행 표(키워드·메모)
5. **대운 분석** — 현재/다음 대운 비교 카드 + 주의점 + 핵심 과제

표·카드의 간지/숫자는 엔진이 제공, AI는 문구만 생성.

### 4.3 백엔드 변경
- Writer 프롬프트: 3단 구성·분량 확대(탭당 200~400자 → 3~4문단), "고민 탭" →
  "추가 주제 탭" 의미 변경, 모던 해설가 톤 명시
- **올해의 흐름·대운 해설 생성 추가** — 리포트 파이프라인에 생성 단계 확장
  (입력: 엔진의 연운·월운·대운 데이터)
- **`SajuReport` 모델 신규**: `id, user_id, profile_id?, birth_input JSON,
  request_topics, tabs JSON, year_flow JSON, dae_un JSON, created_at`
- 리포트 목록/조회 API + share 토큰 발급/열람 API (기존 `share.py` 패턴)
- 프론트 `useSajuApi`에 리포트 메서드 추가 (규칙 준수)

## 4.5 만세력 분석 화면 — "일주 히어로 + 기둥 카드" 재디자인

기존 분석 페이지(profile/calc 결과)를 다음 구조로 재구성한다. **리스킨·재배치이지
기능 축소가 아니다 — 기존 분석 기능은 전량 유지한다** (대운/월운/연운 슬라이더,
일진 캘린더, 합충 패널, 신살 테이블, 강약 바, 지장간, 오행 특성 참고표 등
`components/saju/*` 전체).

1. **일주 히어로 카드** (옐로) — 일주 간지 대형 한자 + "임자일주" + **일주별 한 줄
   캐릭터 카피** (예: "한겨울 바다 위의 달 — 차갑지만 깊은 통찰").
   → 데이터 작업: `rag/knowledge/ilju.json`(60갑자 완비)에서 한 줄 카피 필드
   추출/생성 (LLM 초안 + 검수).
2. **태그 칩** — 격국·용신·강약 + 신살 (칩 규칙 §3 준수)
3. **기둥 카드 8장** — 천간/지지 각 4장, 오행색 배경 틴트 + 잉크 보더, 일주
   기둥만 오렌지 보더 강조. 카드 안에 한자·한글·오행·십성
4. **12운성·신살·지장간 상세** — 접이식
5. **오행 밸런스 카드** — 균형도 N/100 블랙 뱃지 + 오행 5색 가로 바 + 판정 칩
   (과다=오렌지, 부족=틸) + 한 줄 해설. 펜타그램(`WuxingPentagram` 리스킨)은
   바 차트와 탭 전환
6. **십성 구조 카드** — 도넛(중앙 "핵심 구조") + 범례, 구조 요약 바
7. 하단 CTA: [AI 리포트 생성] [상담하기]

**입력폼** (신규 만세력 등록·게스트 입력 공용): 기존 `InputForm` 필드 전량 유지
(이름, 출생지 검색(미입력 시 서울), 생년월일·시각, 시간 모름, 양력/음력/윤달,
성별) — 브루탈 리스킨만 적용.

## 5. 채팅 개편

### 5.1 진입 흐름
상담 탭 → [새 상담] → **채팅 화면 안에서 만세력 선택**(바텀시트) → 세션 생성.
my-profiles를 경유하던 동선 제거. **세션 title 자동 생성** 구현(첫 응답 후 LLM 요약).

### 5.2 만세력 첨부 — 하이브리드
- 입력창 좌측 **`+` 버튼** → 만세력 바텀시트(저장 목록 + 직접 입력) — 선제 첨부 가능
- 첨부 상태는 채팅 상단 **칩**으로 표시, 제거/교체 가능
- 궁합 등 상대방이 필요한 질문 감지 시 **인라인 선택 카드**가 대화 흐름에 등장
- 두 경로 모두 동일한 세션 첨부 상태를 갱신

### 5.3 리치 컴포넌트 (tool 결과 인라인 렌더)
- SSE 스트림에 **tool 호출/결과 이벤트** 추가 노출 (`.astream_events()`가 이미 제공)
- 프론트가 `tool 이름 → 컴포넌트` 매핑으로 말풍선 사이에 인라인 렌더:
  `get_dae_un` → 대운 카드, `get_wol_un` → 월운 차트, `get_daily_fortune` → 점수 카드,
  궁합 tool → 궁합 결과 카드 등. 기존 차트 컴포넌트의 컴팩트 변형 재사용.
  차트 점수 색 의미: 피크=오렌지, 중간=옐로, 저점=틸 틴트. 유저 말풍선=옐로(잉크
  보더), AI 말풍선=화이트(틸 보더) + 마스코트 아바타.
- LLM이 마크업을 직접 출력하는 방식은 배제 (파싱 취약) — tool 결과 기반 결정론 렌더.
- 인라인 선택 카드 트리거도 동일 메커니즘: 에이전트가 `request_partner_profile`
  tool을 호출하면 구조화 이벤트로 프론트에 카드 표시.

### 5.4 백엔드 변경
- `ChatState`/세션에 **상대방 프로필(첨부 만세력) 상태** 추가
- **궁합 tool** 신규 (`get_compatibility_detail` — engine `synastry`/`compatibility` 재사용)
- `request_partner_profile` tool + 구조화 SSE 이벤트
- 세션 title 자동 생성

## 6. 오늘의 운세 — Wrapped 스토리

### 6.0 진입 — 만세력 선택 시트 (필수 선행)
홈 배너 탭 → **"누구의 운세를 볼까?" 바텀시트**: 저장된 만세력 목록(이미 본 만세력은
"오늘 운세 봤음 · 다시 보기" 표시) + [직접 입력하기](입력폼, 게스트 경로) → 스토리 시작.

### 6.1 형식
- 풀스크린 **딥 틸 그라디언트**(`#00857D → #04332F`), **탭 넘김 + 상단 프로그레스 바**
  (오른쪽 탭 = 다음, 왼쪽 탭 = 뒤로, ✕ 닫기). 자동 진행·안내 문구 없음.
  점수는 오렌지(`#FF8A2E`), 프로그레스 바 채움은 옐로. 카드 내 이모지 사용 안 함.
- 카드 시퀀스(~10장): 일진 인트로(마스코트) → 총운 → 시험·금전·애정·직장·건강·대인(6장)
  → 조심할 것 → 행운의 색 → **요약 카드**: 마스코트 + 카테고리별 **가로 점수 바**
  (저점은 오렌지로 구분) + "오늘의 키워드" 타이포 + [이미지 저장]/[링크 공유] 버튼
- **공유는 이중**: ① 요약 카드 **이미지 저장**(클라이언트 캔버스 렌더, 하단에 서비스명
  +링크 워터마크) ② **링크 공유**(기존 `DailyShare` — 받은 사람이 전체 스토리를
  비로그인으로 처음부터 탭해서 봄). 인스타 이미지 → 링크 유입 → 자기 운세 생성의
  바이럴 루프를 노린다.

### 6.2 생성 정책 — 만세력별 1일 1회
- 생성 시 엔진 결과(점수·근거·템플릿 문장)를 **GPT(OpenAI provider)로 1회 리라이트**
  — 직설 친구 톤(반말), 매일 새로운 문장. Strategy Pattern으로 provider만 지정.
- 로그인: `DailyFortuneRecord` 서버 저장 (`user_id, profile_id, date, payload JSON`)
  → 같은 날 재진입 시 저장본 재생, **마이 탭에서 날짜별 기록 열람**.
- 게스트: localStorage 캐시로 동일 동작 (서버 저장 없음).

### 6.3 백엔드 변경
- daily 파이프라인에 GPT 리라이트 단계 + `DailyFortuneRecord` 모델/조회 API
- `OPENAI_API_KEY` 설정 추가

## 8. 에러 처리

- 리포트 생성 실패(LLM 파싱): 기존 `_parse_with_recovery` 유지, 실패 시 저장하지
  않고 재시도 안내 (과금 중복 방지)
- 운세 GPT 리라이트 실패: **엔진 템플릿 원문으로 graceful degrade** (스토리는 항상 뜬다)
- 채팅 tool 이벤트 렌더 실패(미매핑 tool): 인라인 컴포넌트 생략, 텍스트 응답만 표시
- 게스트 localStorage 불가(시크릿 모드 등): 캐시 없이 매번 생성 허용
- 공유 토큰 만료/무효: 기존 share 에러 페이지 패턴
